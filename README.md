Проект: **VELTARQ**


Backend AI-симулятора управления городом «Аким на 5 часов». Сервис принимает пять управленческих решений, проверяет бюджет и ограничения, моделирует их влияние на районы и рассчитывает итоговый Astana Quality of Life Score.

## Моя роль в проекте

Я являюсь backend-разработчиком проекта **VELTARQ** и отвечаю за сервисную архитектуру, бизнес-логику симуляции, API, хранение сценариев, интеграцию AI-аналитики и автоматическое тестирование.

## Реализованный функционал

- каталог пяти районов, десяти показателей и четырнадцати мероприятий;
- единый бюджет в 100 условных единиц;
- проверка ровно пяти решений;
- проверка районных и городских мероприятий;
- контроль повторов, бюджета, направлений и несовместимостей;
- расчёт эффектов с учётом лага на горизонте восьми кварталов;
- применение синергий и ограничение показателей диапазоном от 0 до 100;
- расчёт районных оценок, средневзвешенного городского показателя и итогового Score;
- подсчёт критических показателей со значением ниже 40;
- детализация вклада каждого мероприятия;
- AI-анализ с передачей модели только проверенного результата backend;
- безопасный детерминированный анализ при отсутствии или сбое LLM;
- сравнение двух сценариев;
- подбор улучшенных валидных сценариев;
- сохранение сценариев в SQLite;
- таблица лидеров команд;
- интерактивная документация OpenAPI.

## Формула оценки

Эффект мероприятия с учётом лага:

```text
реализованный эффект = полный эффект × (8 − лаг) / 8
```

Итоговая оценка:

```text
Score = 0,7 × D_avg + 0,3 × min(D_района) − N_crit
```

`D_avg` — средневзвешенная по населению оценка города. `N_crit` — число пар «район × показатель» со значением строго меньше 40. Промежуточные значения не округляются.

Контрольные значения из исходного датасета:

- базовый Score: `52.55768`;
- Score контрольного сценария: `56.54307`;
- изменение: `+3.98539`.

## Архитектура

```text
app/
├── api/routes.py              HTTP API
├── catalog.py                 исходные данные симулятора
├── domain.py                  доменные типы
├── schemas.py                 входные и выходные модели API
├── services/
│   ├── validation.py          проверка правил
│   ├── simulation.py          расчётный движок
│   ├── recommendation.py      поиск улучшенных сценариев
│   ├── analysis.py            детерминированное объяснение
│   ├── llm.py                 интеграция AI и fallback
│   └── repository.py          хранение в SQLite
└── main.py                    создание FastAPI-приложения
```

Backend является единственным источником числовой истины. LLM не рассчитывает показатели и Score: она получает готовый JSON, объясняет изменения, риски и компромиссы. Любая рекомендация должна повторно проверяться расчётным движком.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
uvicorn app.main:app --reload
```

Linux или macOS:

```bash
source .venv/bin/activate
python -m pip install -e ".[dev]"
uvicorn app.main:app --reload
```

После запуска:

- API: `http://localhost:8000`;
- Swagger UI: `http://localhost:8000/docs`;
- OpenAPI JSON: `http://localhost:8000/openapi.json`;
- проверка состояния: `http://localhost:8000/health`.

## Запуск через Docker

```bash
docker compose up --build
```

База данных сохраняется в каталоге `data` на хосте.

## Настройка AI

Без внешней модели сервис использует детерминированное объяснение результатов. Для подключения OpenAI-совместимого API скопируйте `.env.example` в `.env` и заполните:

```dotenv
VELTARQ_LLM_BASE_URL=https://example.com/v1
VELTARQ_LLM_MODEL=model-name
VELTARQ_LLM_API_KEY=secret
```

Если AI-сервис недоступен, backend автоматически возвращает проверенное локальное объяснение. Расчёт симуляции продолжает работать независимо от AI.

## Основные endpoints

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/health` | состояние сервиса |
| `GET` | `/api/v1/catalog` | районы, показатели, мероприятия и правила |
| `POST` | `/api/v1/scenarios/validate` | проверка сценария |
| `POST` | `/api/v1/scenarios/simulate` | полный расчёт сценария |
| `POST` | `/api/v1/scenarios/analyze` | расчёт и AI-объяснение |
| `POST` | `/api/v1/scenarios/compare` | сравнение двух сценариев |
| `POST` | `/api/v1/scenarios/recommend` | поиск улучшенных вариантов |
| `POST` | `/api/v1/scenarios/save` | сохранение результата команды |
| `GET` | `/api/v1/scenarios/{id}` | получение сохранённого сценария |
| `GET` | `/api/v1/leaderboard` | таблица лидеров |

Пример запроса:

```json
{
  "decisions": [
    {"measure_id": "M7", "district_id": "nura"},
    {"measure_id": "M8", "district_id": "nura"},
    {"measure_id": "M10", "district_id": "nura"},
    {"measure_id": "M12"},
    {"measure_id": "M5", "district_id": "saryarka"}
  ]
}
```
