# Astana Atlas

Основное приложение: React + TypeScript + Vite + 2GIS MapGL, подключённое к FastAPI backend из [ветки integration](https://github.com/BAITC-Hacks/hack-8b6eaa99-veltarq/tree/integration). Пользователь выбирает районы, составляет план из 14 мероприятий и сравнивает исходные показатели со сценарием через 8 кварталов. Итоговый расчёт, объяснение, сравнение и поиск улучшений выполняет сервер. Карта, её оформление и стили сохранены.

## Запуск

```bash
npm ci
npm run setup:backend
```

Требуется Node.js, совместимый с Vite 8, и Python 3.11+. `setup:backend` создаёт `backend/.venv` и устанавливает зависимости. При необходимости укажите путь к Python в переменной `PYTHON`.

Скопируйте `.env.example` в `.env.local` и заполните `VITE_2GIS_KEY`. Уже настроенный `.env.local` заменять не нужно. Файл исключён из Git. После изменения ключа перезапустите Vite.

```bash
npm run dev
```

`npm run dev` запускает обе части: сайт на http://127.0.0.1:5175/ и backend на http://127.0.0.1:8000/. Порт сайта фиксирован, поскольку ограничения браузерного ключа учитывают адрес сайта. Если Vite уже запущен, достаточно `npm run dev:backend`. Отдельный запуск frontend: `npm run dev:web`. Ctrl+C завершает дочерние процессы запуска.

```bash
npm test
npm run test:backend
npm run test:integration
npm run build
```

Сборка проверяет GeoJSON, TypeScript и создаёт `dist`. Для публикации ключ должен присутствовать в окружении **во время сборки**. `test:integration` сам запускает изолированный backend на свободном локальном порту и проверяет реальный HTTP-контракт: каталог, 50 показателей примера, рекомендации и сравнение. Внешняя LLM для этих тестов не вызывается.

## Подключение backend

Исходники включены в `backend/`; ветка, commit и изменения перечислены в `backend/UPSTREAM.md`. Вложенного Git-репозитория нет. Числовой движок исходного backend сохранён.

По умолчанию браузер обращается к `/api/v1`; Vite проксирует `/api` и `/health` на `http://127.0.0.1:8000`. Для внешнего сервера задайте `BACKEND_URL` в `.env.local` (прокси разработки) или полный `VITE_API_BASE_URL=https://api.example.com/api/v1` (встраивается при сборке). Для другого локального порта установите `BACKEND_PORT` перед запуском обеих частей; явный `BACKEND_URL` имеет приоритет. Для прямого обращения браузера разрешите origin сайта в `VELTARQ_CORS_ORIGINS` на backend.

`npm start` после сборки обслуживает API и `dist` одним сервером на http://127.0.0.1:8000. Для такого адреса или рабочего домена требуется разрешённый Origin ключа 2ГИС. При отдельном статическом размещении сайта backend должен быть развёрнут отдельно и указан через `VITE_API_BASE_URL`; одна загрузка `dist` не запускает Python.

`src/api.ts` переводит названия районов в серверные ID (`Нура` → `nura`), проверяет структуру ответа и переносит серверный Score без пересчёта. Перед расчётом `/catalog` сверяется с локальными данными, весами, мерами, синергиями и правилами. При несовпадении версий, ошибке API, превышении времени ожидания или отклонённом плане результат не показывается; план остаётся доступным для исправления и повторной попытки. Правка плана отменяет запросы и аннулирует старый результат.

## Анализ и улучшение плана

После расчёта откройте «Мой план» → «Анализ и улучшение плана». Здесь доступны объяснение результата, риски, компромиссы, вклад мероприятий, синергии и поиск улучшений. «Сравнить с текущим планом» рассчитывает оба набора через backend, затем запрашивает их объяснение у LLM. «Применить вариант» обновляет существующий редактор и автоматически запускает новую проверку, серверный расчёт и объяснение. Поиск рассматривает замену или перенос одной меры и находит улучшения по Score; глобальный максимум не обещается.

Для LLM скопируйте `backend/.env.example` в `backend/.env` и заполните `VELTARQ_LLM_BASE_URL`, `VELTARQ_LLM_MODEL`, `VELTARQ_LLM_API_KEY`; `VELTARQ_LLM_TIMEOUT_SECONDS` задаёт время ожидания (по умолчанию 20 секунд). Затем перезапустите backend. Скрипты запуска загружают этот файл. Выбрана `gpt-6-luna` с адресом `https://api.openai.com/v1` и `VELTARQ_LLM_API_MODE=responses`; ключ нужен от вашего серверного проекта OpenAI. Astra доступна заменой модели на `gpt-6-astra`. Для других совместимых провайдеров сохранён режим `chat_completions` (также используется при отсутствии переменной API_MODE). [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra).

Ключ хранится только на сервере, без префикса `VITE_`; `backend/.env` исключён из Git. В браузер отправляются только рассчитанные данные и проверенное объяснение. Не помещайте ключ в адрес провайдера, frontend-переменные или логи.

LLM получает полный серверный результат: Score до/после, районные показатели и дельты, вклад каждой меры и синергий, бюджет и оставшиеся критические показатели. Модель выбирает и упорядочивает ссылки на серверные факты по разделам. Backend проверяет структуру JSON, допустимость ссылок, соответствие разделам и обязательные факты; текст и числовые значения подставляет само приложение. Произвольные утверждения или числа модели не отображаются. При сравнении LLM получает оба рассчитанных результата и их серверные различия.

Без настройки, при отказе, таймауте или некорректном ответе показывается **«Автоматическое объяснение без ИИ»** с причиной и повторным запросом. Расчёт через `/scenarios/simulate` отображается до завершения AI-запроса; ошибка объяснения не удаляет Score. Правка плана отменяет запросы расчёта, объяснения, поиска и сравнения и скрывает устаревшие ответы, включая поздний ответ после отмены. Сохранение плана в браузере работает независимо от API.

После заполнения серверных настроек можно явно проверить живого провайдера:

```bash
npm run test:llm
```

Эта команда выполняет два реальных запроса: объяснение примера из ТЗ и сравнение с рассчитанным улучшением. Успех требует `provider=llm` и валидных ссылок в обоих ответах; fallback не считается успехом. При неполных настройках сетевой запрос не выполняется. Секреты и сырые ответы провайдера не печатаются. Обычные `npm test`, `test:backend` и `test:integration` проверяют расчёт, ошибки, отмену и весь путь с моками/детерминированным объяснением; они не подтверждают доступ к живой LLM.

## Ключ 2ГИС

`VITE_2GIS_KEY` встраивается в браузерный код и доступен пользователям. `.env.local` защищает от случайного коммита, но не скрывает ключ в браузере.

В кабинете 2ГИС: **Ключи API → нужный ключ → Ограничения → По HTTP-заголовкам**. Для этого локального экземпляра сохранены разрешённые `Origin`: `http://127.0.0.1:5175` и `http://localhost:5175`. При переходе на другой порт или рабочий HTTPS-домен добавьте соответствующий адрес в разрешённые значения в кабинете: введите адрес, нажмите Enter, затем «Сохранить изменения». Ограничения применяются ко всем сервисам ключа; учитывайте другие приложения, если ключ общий.

При ошибке доступа проверьте активность ключа, подключённый MapGL JS API, разрешённый Origin и подписку. Рабочий домен пока не предоставлен и не добавлен.

Документация: [управление ключами](https://docs.2gis.com/platform-manager/subscription/managing-keys), [управление пробками](https://docs.2gis.com/en/mapgl/map/configuration/controls), [события MapGL](https://docs.2gis.com/en/mapgl/reference/interface#trafficscore).

## Интерфейс

Светлая компоновка перенесена из `.frontend-workbench/sessions/astana-playfield-redesign/product-design/preview/`: карта занимает основную рабочую область, сверху находятся меню, переключение «До / После», Score, кнопки «Мой план» и «Весь город». Нижняя панель содержит пять районов с силуэтами из GeoJSON и индексами; её можно скрыть кнопкой меню и развернуть снова.

Выбор района открывает карточку справа. «Мой план» открывает отдельную панель слева с бюджетом, выбранными мерами и расчётом. «Подобрать меры» в карточке или «Каталог мероприятий» в нижней панели открывают каталог. Панель плана закрывается при выборе района, открытии каталога и переходе к рассчитанному сценарию. На мобильном экране панели адаптируются к ширине и высоте окна.

Шрифт Onest загружается локально из `public/fonts/Onest.ttf`; лицензия находится в `public/fonts/OFL.txt`. `src/DistrictSilhouette.tsx` формирует силуэты непосредственно из существующих игровых границ.

## Режим «До — сейчас»

- Официальный дорожный слой пробок включается автоматически в «До» через `trafficOn` / `showTraffic` и скрывается в «После» через `hideTraffic`.
- Отдельные панель пробок, балл и переключатель пробок в интерфейсе скрыты. Пробки доступны как дорожный слой на карте.
- `src/useTraffic.ts` продолжает обрабатывать `trafficscore` внутри приложения независимо от учебных индексов. Оценка не трактуется как балл выбранного района; пустые, некорректные и служебные значения не превращаются в ноль. Принимаются только целые баллы 1–10.
- Внутреннее состояние различает ожидание, отсутствие оценки через 15 секунд, ошибку и устаревание через 5 минут без нового события. Эти локальные интервалы не являются сроками актуальности данных провайдера. Обработчик принимает поздние события; `trafficshow` и готовность базовой карты не подтверждают получение оценки.
- Время получения события хранится как время получения приложением, а не время измерения: SDK не передаёт время измерения провайдером. В текущем интерфейсе это время не выводится.
- Ошибки загрузки карты сопровождаются сообщением и кнопкой повторной загрузки. Недоступность карты не мешает составлению и расчёту плана.

## Районы, мероприятия и сохранение плана

Клик по району на карте или в нижней панели открывает карточку с десятью исходными показателями T1–C2, индексом района и долей населения из учебного датасета. T1 «Разгрузка дорог» берётся из учебной модели и отображается в карточке; данные пробок 2ГИС хранятся отдельно и не участвуют в расчёте T1 или Score.

«Подобрать меры» открывает каталог всех 14 мероприятий с направлением, стоимостью, лагом, областью действия и предварительными изменениями показателей. Предпросмотр сравнивает текущий план с планом после добавления меры: учитывает лаги, синергии и ограничения показателей. Для районных мер можно выбрать целевой район; городские действуют на все пять районов.

Предпросмотр запрашивается через `/scenarios/preview`: сервер использует тот же `SimulationEngine` для текущего неполного плана и допустимых добавлений, возвращает готовые значения и дельты. Остальные ограничения сохраняются; Score неполного плана не возвращается. При недоступном сервере вместо выдуманного предпросмотра показывается ошибка и повтор запроса.

План показывает бюджет и число решений, позволяет удалять меры и менять район. Для итогового расчёта нужны ровно 5 разных мероприятий, стоимостью не более 100 и не более 2 мероприятий одного направления. M1 и M3 несовместимы во всём плане; M4 и M7, а также M5 и M13 — только в одном районе. Все пять направлений одновременно не обязательны. Неприменимые добавления отключены с объяснением причины.

`src/useSavedPlan.ts` сохраняет план в `localStorage` под ключом `astana-atlas-plan-v1` и восстанавливает его после перезагрузки. Сохраняются ID мер и целевые районы; результаты рассчитываются заново. Повреждённое хранилище и невозможность сохранения имеют отдельные сообщения. Список районов, каталог и расчёт доступны даже при недоступной карте 2ГИС.

## Расчёт и режим «После — сценарий»

`src/modelData.ts` содержит типизированный каталог, исходные показатели, веса и доли населения из [ТЗ](https://docs.google.com/document/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/edit), сверенные с приложенным PDF. `src/model.ts` переносит арифметику исходного аудита в чистые функции TypeScript: `validatePlan` проверяет ограничения; `calculateEffects` и `calculatePlan` сохранены для контрольных проверок модели и исходного состояния. Последствия добавления мер UI получает через `/scenarios/preview`, итог — через `/scenarios/simulate`, затем независимо запрашивает объяснение через `/scenarios/analyze`.

Горизонт расчёта — 8 кварталов. Эффект меры умножается на `(8 − лаг) / 8`. Синергии M1 + M2 → T1, M10 + M12 → B1 и M5 + M6 → E2 добавляют по 2 пункта без лага в районе соответствующей районной меры. После всех эффектов и синергий показатели ограничиваются диапазоном 0–100. Расчёт ведётся в восьмых долях пункта без промежуточного округления.

Индекс района D — сумма показателей с весами из ТЗ. `Score = 0,7 × средний D с учётом долей населения + 0,3 × минимальный D − количество показателей строго ниже 40`. Значение 40 не даёт штраф. Тесты сверяют все показатели, районные индексы и Score с `src/test-fixtures/audit_results.json`, включая контрольные результаты:

- Базовый Score: **52.55768**.
- Пример из ТЗ: M7, M8 и M10 в Нуре, M12 для города и M5 в Сарыарке; бюджет **95**, Score **56.54307**. Пример можно загрузить из пустого плана.

Итоговый Score показывается только после расчёта допустимого плана. В режиме «После» карточки показывают «до → после», изменения показателей и индексов районов. Переключение режима сохраняет положение и масштаб карты, скрывает живые пробки и показывает объекты только выбранных мероприятий. Изменение плана возвращает интерфейс в «До».

`src/scenarioGeometry.ts` связывает каждый объект с `measureId` и `districtId`. Районная мера получает объект в своём районе, городская — условный маркер охвата в каждом из пяти районов. Объекты и границы демонстрационные; прирост T1 не превращается в уменьшение времени поездки или окраску конкретной дороги.

- `src/data/districts.geojson` — пять игровых зон, не официальные административные границы.
- `src/data/projects.geojson` — условные школы и парки; внутренние точки используются как опоры размещения объектов.
- `src/data/decisions.geojson` — демонстрационные геометрии; контуры школы и парка используются для выбранных M7 и M4.
- `src/data/metrics.json` — архивные заранее заданные значения прежнего макета; основное приложение и проверка данных их не используют.

`npm run validate:data` проверяет пять уникальных районов, структуру GeoJSON, точки внутри соответствующих районов и типы демонстрационных объектов. Проверки модели, сохранения, карты и интерфейса запускаются через `npm test`.

## Архивные макеты

Отдельные предыдущие макеты остаются в `.frontend-workbench/`. MapLibre сохранён только как **dev-зависимость** для этих макетов. Основное React-приложение и его production bundle используют 2GIS MapGL. Старый прокси `/tiles` также нужен только архивным макетам.
